# Companion Artifacts Directory

This directory holds companion artifact files generated by spec skills during specification authoring.

## Naming Convention

Each spec gets its own subdirectory named `<NNN>-<idea-name>/`, matching the spec file name:

```
.sdd/specs/artifacts/
  001-reviewer-v2/
  002-spec-architect-v2/
  ...
```

The coordinator creates this subdirectory before dispatching any skill that produces code artifacts (FR-008).

## Expected Artifact Files

Skills that define technical contracts produce companion artifact files in these subdirectories. The standard artifact file names are:

| File | Produced by | Purpose |
|------|-------------|---------|
| `data-models.<ext>` | spec-data-model | Typed entity definitions, field types, validation rules |
| `state-machines.<ext>` | spec-data-model | State transition definitions for stateful entities |
| `api-contracts.<ext>` | spec-api-design | Endpoint/interface signatures, request/response schemas |
| `error-catalog.<ext>` | spec-api-design | Error codes, messages, HTTP status mappings |
| `interfaces.<ext>` | spec-api-design | Public interface/type definitions |
| `config-schema.<ext>` | spec-architecture | Configuration option definitions with types and defaults |

## File Extensions by Target Language

The file extension matches the target language specified in the spec's technology stack:

| Language | Extension |
|----------|-----------|
| TypeScript | `.ts` |
| Python | `.py` |
| SQL DDL | `.sql` |

## Target Language Selection (FR-015)

The target language for companion artifacts is determined by:

1. **Primary**: Use the language specified in the brief/spec's technology stack section
2. **Default**: If the target language is not yet determined when a skill runs, use **TypeScript** as the default and note the assumption

## Manifest Comment Format (FR-028)

Every companion artifact file SHALL include a manifest comment at the top:

```
// Generated by: spec-<skill-name> skill
// Source spec: .sdd/specs/<NNN>-<idea-name>.spec.md, Section <N>
// Target language: <language>
// DO NOT EDIT MANUALLY -- regenerated on spec revision
```

For Python files, use `#` comment syntax instead of `//`.
For SQL files, use `--` comment syntax instead of `//`.
