## Objective

Implement the final Phase 2 skill: `plan-cross-wp-validation`. This skill is the capstone of the planning pipeline -- it reads ALL plan files and ALL contract files generated by earlier skills, performs a 7-point consistency audit (data contracts, API/interface contracts, dependencies, configuration, test requirements, spec traceability, contract-to-task alignment), generates a shared configuration schema, fixes any inconsistencies, and documents corrections.

## Spec References

FR-051, FR-052, FR-053, FR-054, Section 4.10, Section 7.2

### T19-02 - Implement data contract consistency check

- **Description**: Write instructions for checking that entity fields (names, types, validation rules) are identical across all WPs that reference the same entity. Flag and fix mismatches.
- **Spec refs**: FR-051.1
- **Parallel**: Yes (with T19-03, T19-04, T19-05, T19-06, T19-07)
- **Acceptance criteria**:
  - [x] The skill SHALL verify entity fields match across WPs (FR-051.1)
  - [x] If WP-A defines field `userId: string` and WP-B defines `userId: number`, the skill SHALL flag it and fix to the canonical type from the spec data model
  - [x] Shared data formats (dates, IDs, enums) SHALL be consistent across all WPs
  - [x] Fixes are applied directly to the contract files, not just reported
- **Test requirements**: BDD (US-04 Scenario 1)
- **Depends on**: T19-01
- **Implementation Guidance**:
  - Canonical types come from the spec's data model (Section 7)
  - When two WPs disagree, the spec is the tiebreaker

## Implementation Notes

- This is the only skill that depends on ALL other plan skills having produced their output
- It reads both the plan files (.sdd/plans/WP*.md) and the contract files (.sdd/plans/contracts/**)
- The config schema is the only output that goes to `contracts/shared/` (all other contracts are per-WP)
- This skill naturally runs last in the Phase 2 sequence

## Parallel Opportunities

- T19-02 through T19-07 (the six consistency checks) can all run in parallel since they read the same inputs independently
- T19-08 (fix + document) and T19-09 (100% coverage) must run after all checks complete

## Risks & Mitigations

- **Risk**: Large specs generate many contract files, making cross-WP validation slow. **Mitigation**: The skill operates within a single context window and uses structured comparison (not line-by-line diffing).
- **Risk**: Auto-fix may introduce new inconsistencies. **Mitigation**: Consistency notes document every change; the Coder can review during implementation.
